What is checked

  1. IntegritySHA-256 of the file equals the hash stored in the signature.
  2. SignatureThe public key opens the signature: se mod n gives that hash (RSA), or the ECDSA equation holds.
  3. TrustThe certificate chain leads to a root in the trust store.
  4. ValidityCertificates were valid when the file was signed; the algorithm is not weak.

How it works

Four ideas from discrete mathematics, each computed from scratch in this project.

The four steps

#StepFormulaDiscrete maths behind it
1Hashh = SHA-256(document)A 256-bit fingerprint; one changed byte changes h completely. Collisions exist (pigeonhole principle) but cannot be found.
2Sign (private key)s = hd mod nn = p·q with primes from Miller–Rabin; d = e−1 mod φ(n) by the extended Euclidean algorithm.
3Verify (public key)se mod n = h ?Works because e·d ≡ 1 (mod φ(n)), with Fermat/Euler and the CRT; computed by square-and-multiply.
4Trust (PKI)Root CA → CA → SignerEach certificate is signed by its issuer with the same maths; the path must end at a trusted root.

Attacks: why the rules matter

Break a small key

Factoring n gives p, q, φ(n) and the private key d. Up to 64 bits.

Forge "textbook" RSA

Without hashing, (s1·s2)e = m1·m2, so signatures can be combined.
